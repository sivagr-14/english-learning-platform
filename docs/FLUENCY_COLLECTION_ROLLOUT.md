# Fluency collection rollout

## Implemented in this branch

- Taxonomy 2026.3: 500 categories; the existing 440 keys remain stable. New
  domains cover professional communication, linking ideas and conversational
  nuance. 2026.1 and 2026.2 manifest compatibility is tested.
- Quick lesson view, realistic conversation prominence, a pattern/contrast/
  memory cue, answer-before-reference practice, expandable eight-section detail
  and owner-scoped links to other senses of the same spelling.
- Practice by recognition, recall, listening, speaking and writing; focus paths,
  CEFR/register/search filtering, diagnostic gap checks, due practice and
  revisiting mistakes. Responses and reflections are stored per contextual
  sense. Self-assessment is labelled explicitly.
- Browser speech playback and tab-local record/replay. No speech is sent to a
  grading service; no automatic pronunciation or semantic score is claimed.
- Personal examples, additive tags, correction notes and active/recognition-only
  intent. Skill schedules use the learner's timezone; same-day repetitions do
  not inflate retention evidence. Production requires delayed use and context
  variation. Explicitly choosing an entry or diagnostic session can go beyond
  the daily new-entry suggestion.
- Coverage includes empty categories and CEFR counts. A cancellable, paginated
  contract audit exports exact issues. It is not a semantic duplicate,
  provenance, corpus-frequency or editorial audit.
- Collection request export with current matching vocabulary and catalogue.
  Immutable index CLI groups accepted units into visible packs of up to 400;
  a registered-pack ledger reconciles hashes, counts, database verification and
  per-candidate editorial review receipts. The 100-pack estimate is a planning
  goal, never fabricated candidate membership.
- SQL-only missing review-row creation, bounded introductions, learner locks,
  transactional flashcard scheduling, validated limits and idempotent review
  receipts. Existing sense ranks, lesson identities and historical progress
  remain stored. Flashcard statistics describe recall rather than fluency.

## Deployment and real-data handoff

1. Review and merge the PR after its checks pass. Do not call a draft PR deployed.
2. On the Mac, use the existing Update & Restart flow. It backs up PostgreSQL
   and applies migrations. No remote agent has inspected the user's database.
3. Open Coverage & Collection and run/download the contract audit. Review
   frequency, semantic duplicates, provenance and teaching quality separately.
4. Select Prepare collection request for ChatGPT. Attach that JSON to the
   conversation. This supplies the real baseline needed to avoid duplicate
   content and is not a complete assessed candidate list.
5. Assess catalogue coverage and a representative pilot using the nested topic
   contract. Freeze complete validated manifests before generating lessons.
   Pilot: roughly 400 useful entries with varied expression types, levels and
   situations; do not force a source's discovery count to 400.
6. Deliver validated internal units through the GitHub App to the existing inbox.
   Preserve all current automatic ownership/import/read-back rules.
7. Create and register the immutable collection index and editorial review
   records. Expand only after pilot quality and learner experience are checked.
8. Reconcile actual unique senses, exclusions, missing units, review evidence and
   committed entries throughout expansion. Existing quality-checked entries
   reduce the new work required to reach 40,000.

No 40,000-entry collection or 400-entry pilot has been generated by this code
change. No candidate frequency evidence has been fabricated. Real-data audit
and collection assessment remain blocked on the local account export.

## Remaining capabilities, explicitly not claimed

- A1/A2 foundation-gap generation needs a separately versioned topic selection
  contract; the default B1–C2 policy has not been silently changed.
- Diagnostic sessions are self-assessed gap checks, not an adaptive CEFR exam.
- Automated free-response evaluation, pronunciation scoring and live AI role
  play require a separately selected capability; current practice uses imported
  scenarios, self-comparison, browser audio and recording.
- Audio recordings are not persisted or uploaded. Saved text responses can be
  compared over time. Professionally recorded audio is not bundled.
- Source-frequency evidence and language/teaching review are editorial records;
  schema validation cannot prove linguistic truth or native-speaker competence.
- Correcting lesson content still uses the existing complete versioned import
  contract; a learner correction note is not an automatic content replacement.
- Collection indexes and review records can be registered in the app; their
  transfer is not yet part of the automatic inbox scanner.
- Actual ChatGPT Project attachments are separate from the repository's mirrored
  instruction files and are not replaced by creating or merging this PR.

## Validation

- Backend unit suite, backend/frontend type checks and lint.
- Full database migrations applied in an isolated PostgreSQL-compatible engine.
- API smoke checks: account isolation, distinct sense progress, duplicate request
  handling, immutable pack registration/reviews, audit/coverage, shared budgets,
  review scheduling and 40,000-entry queue creation.
- Playwright checks cover production practice, empty-category coverage, audit
  labelling, quick lesson detail and related meanings using explicit fixtures.
- CI repeats migrations and smoke checks against PostgreSQL 16, plus the existing
  content-pack, sense and category workflows.
